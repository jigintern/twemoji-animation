# 蝶アイコン (アニメーション WebP)

羽ばたきの常時ループ。

`./build.sh` が `butterfly.webp` を作る。
192x192 / ロスレス / 背景透明 / 20 フレーム / 1 フレーム 25ms / 1 周期 500ms / `Loop Count 0` (無限ループ) / 77396 bytes。

## 素材

Twemoji の `1f98b.svg` (🦋) を使う。
`https://raw.githubusercontent.com/jdecked/twemoji/main/assets/svg/1f98b.svg`

ライセンスは CC-BY 4.0。
利用する画面に帰属表記を置く。
置く 1 行はリポジトリ直下の [NOTICE](../../NOTICE) にある。

path 11 本で、5 本ずつが片方の羽にあたる。

| 範囲 | 中身 |
| --- | --- |
| 0〜4 | 右の羽 (x 17.9〜35.9) |
| 5〜9 | 左の羽 (x 0.1〜18.2) |
| 10 | 胴体 (x 13.9〜22.2、中心 18.1) |

片羽の内訳は `#1C6399` の下地 2 本、`#55ACEE` の模様 1 本 (7 subpath)、`#292F33` の縁 2 本。
左右が x=18 でちょうど分かれるので、羽を独立に動かせる。

## 作り直す

```sh
./build.sh
```

出力先は `OUT` で変えられる。
`OUT=../../dist/butterfly.webp ./build.sh` はディレクトリを作ってから書く。

パラメータは環境変数で振れる。

```sh
SQX=0.20 N=28 DUR=18 ./build.sh
```

| 変数 | 既定 | 意味 |
| --- | --- | --- |
| `SIZE` | 192 | 出力の 1 辺 (px) |
| `N` | 20 | 1 周期のフレーム数 |
| `DUR` | 25 | 1 フレームの表示時間 (ms)。`N * DUR` が 1 周期 |
| `SQX` | 0.28 | 羽が最も閉じたときの scaleX。1.0 が全開 |
| `SCY` | 1.06 | 羽が立ったときの scaleY。閉じるぶん縦に伸ばす |
| `LIFT` | 0.9 | 胴体の上下動 (svg 単位) |
| `AXIS` | 18.1 | 羽を畳む軸。胴体の中心 |
| `CY` | 18.0 | scale の縦中心 |
| `WARP` | 1.0 | 時間の非対称。1 未満で閉じるのが速く、開くのが遅い |

`gen.py` は 2 パスで動く。
1 パス目で全フレームのバウンディングボックスの和を測り、切れない最小の viewBox を決める。
2 パス目でその viewBox を全フレームに固定して SVG を吐き、`resvg` でラスタライズする。

`frames/` は生成物なので追跡しない。
`frames/duration` に 1 フレームの ms を書き出し、`build.sh` がそれを読んで `img2webp -d` に渡す。
`N` と表示時間の対応が 1 箇所に収まる。

## 決めた理由

羽の畳みは胴体軸に向けた scaleX で表す。
Twemoji の 🦋 は真上から見た構図なので、羽が立ち上がると真上からは横幅が縮んで見える。

`SQX` は 0.28。
0.25 / 0.38 / 0.50 を比べると、0.50 では閉じても幅が残って羽ばたきが弱く、0.25 付近で動きが最も明確になる。
0.28 でも羽の形は保たれる。

`WARP` は 1.0 のまま。
0.75 にすると開いている時間が長くなり、打ち下ろしと打ち上げがほぼ対称な蝶の羽ばたきから外れる。

## 採らなかった方法

胴体側を支点に左右の羽を回転させる。
真上から見た構図なので、回転させると羽が下へ垂れて胴体を横切り、羽ばたきではなく羽を畳む動きになる。
支点を (18.1, 18.0) に置いて 34 度まで回した比較で確認した。

`-lossy` や `-near_lossless` でサイズを削る。
`-lossy -q 85` は 103972 bytes と逆に増える。
`-near_lossless 60` は `-lossless` と併用しても出力が変わらない。
サイズはフレーム数が支配していて、20 フレームの 77396 bytes に対し 14 フレームでは 54064 bytes になる。
